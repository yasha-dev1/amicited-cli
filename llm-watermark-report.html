Evidence directory · research snapshot

LLM watermark removal is not one problem—and no public tool proves it solves the provider problem.

A source-led audit of 26 GitHub repositories covering statistical text watermarks, Unicode artifacts, metadata/C2PA, image marks, paraphrase attacks, and generic AI classifiers. Built to guide a defensible free tool for AmICited.

Bottom line: no audited repository demonstrates reliable, current, provider-specific removal of OpenAI text, Anthropic text, or Gemini production text watermarks. Most “removers” either delete a fixed list of invisible Unicode characters, rewrite text, strip file metadata, or test academic schemes with known secret keys. Those can be useful—but they are different claims.

Provider reality check

Provider branding is not a detection method. A tool can call Claude, GPT, or Gemini to paraphrase text without detecting—or specifically removing—the provider’s watermark.

Six things called “watermark”

The repositories divide into distinct technical layers. Conflating them produces false positives and misleading “100% removed” claims.

1. Statistical text mark

A secret-key bias changes which tokens an LLM selects. Detection tests whether token patterns are unexpectedly aligned with the key.

2. Invisible Unicode

Zero-width characters, variation selectors, bidirectional controls, and unusual spaces embedded directly in text. Deterministic sanitation is possible.

3. AI-style classifier

A probabilistic model guesses whether prose looks machine-generated. It neither reads nor removes a cryptographic/statistical watermark.

4. Metadata / C2PA

Provenance stored in a file container or signed manifest. Stripping metadata removes the record, not necessarily invisible pixels or token patterns.

5. Visible media mark

A logo or overlay in pixels/video frames. Cropping, masking, or inpainting is a visual-editing operation.

6. Invisible media mark

A signal embedded in image, audio, or video content. Robust systems can survive metadata removal and ordinary transformations.

Method and evidence scale

Discovery

GitHub repository and code searches combined provider terms, “watermark,” “detector,” “remover,” “paraphrase,” “SynthID,” “C2PA,” and known academic scheme names. References and related work were followed until searches repeated the same projects.

Audit

For each repository, the audit inspected ownership, license, activity, implementation path, detector assumptions, reported evaluation, tests/CI, issue evidence, and whether provider claims were actually connected to provider-specific code.

Limits

This is a point-in-time, best-effort public-code directory—not an eternal or mathematically exhaustive census. Stars and activity are snapshot indicators. Closed, private, renamed, newly published, or search-invisible projects may be absent.

Evidence rank: Official reference provider/algorithm source; Peer-reviewed academic artifact with stated evaluation; Self-tested project-owned fixtures or demos; Claim only no meaningful validation found. Even strong academic evidence on a known-key scheme is not production-provider proof.

Detector truth states

Binary “watermark found / removed” UI is unsafe when most provider checks are impossible. Use explicit operational states.

detected

The configured detector found evidence above its calibrated threshold. Name the scheme, configuration, length, score, and threshold.

not_detected

The configured detector did not cross its threshold. This is not “human-written” and not proof that another detector would agree.

not_configured

The implementation supports a scheme, but no valid key/configuration/calibration was supplied.

unsupported

The input modality or claimed provider has no compatible detector.

unverifiable

A transformation ran, but no authoritative before/after detector is available.

failed

Parsing, model execution, provider access, or validation failed. Never convert this into “clean.”

What AmICited should build

A provenance inspector and research-grade transformation workbench—not a universal “watermark remover.”

  1. Local hidden-character inspector. Highlight exact code points and categories; offer reversible, selectable cleanup that preserves line breaks, code, RTL text, and typography by default.
  2. File provenance inspector. Read C2PA and metadata without mutating the original. Explain signature validity, issuer, actions, and the difference between removal and invalidation. Export a change manifest.
  3. Known-scheme research detector. Support transparent KGW/Unigram/EXP/SynthID-reference configurations only when users provide exact keys/configs. Show raw score, threshold, token count, and calibration.
  4. Privacy-first rewrite with review. Provide sentence-level diff, protected spans for citations/code/numbers, semantic-drift warnings, local processing where possible, and clear API disclosure where not.
  5. Truthful status and copy. Say “hidden characters removed,” “metadata removed,” or “configured research detector no longer fires.” Never say “OpenAI/Anthropic/Gemini watermark removed” without an authoritative provider detector.

SEO-safe positioning: a landing page can address the search term while immediately clarifying scope: “Check and clean hidden text artifacts, metadata, and supported research watermarks. Provider-private marks may be unverifiable.”

MVP

Unicode inspection, exact diff, C2PA/metadata read-only scan, copy-safe cleanup, transparent status model, local processing, exportable report.

Research beta

Bring-your-own known-scheme key/config; before/after score; length warning; curated paraphrase with semantic/human review; reproducible run manifest.

Do not promise

Universal provider detection, proof of human authorship, guaranteed evasion, anonymous provenance destruction, or classifier score as watermark verification.

Risk, ethics, privacy, and product controls

Integrity

Watermark/provenance removal can facilitate misattribution, policy evasion, or deceptive media. Preserve originals, show warnings, log only with consent, and avoid “undetectable” marketing.

Quality

Paraphrase and translation can corrupt quotations, citations, numbers, code, legal meaning, and authorial voice. Protect spans and require visible human acceptance.

Security & accessibility

Homoglyphs, bidi controls, and zero-width insertion create phishing and screen-reader hazards. Detect them; do not generate them as an evasion strategy.

Privacy

Text sent to third-party paraphrase APIs may be retained or sensitive. Default to local inspection; disclose provider, region, retention, cost, and data flow before upload.

Licensing

MIT/Apache research code is easier to evaluate for reuse; AGPL can impose network-source obligations; missing or mixed licenses mean do not copy code without permission.

Provenance law & policy

EU AI Act Article 50 transparency duties apply from 2 Aug 2026. Product counsel should review intended use, platform terms, and record-removal behavior; this report is not legal advice.
